## Этап 3: H1 и H2 на chronos-bolt-small (2026-10-30)

`python -m scripts.stage3_failures` → `results/stage3/chronos-bolt-small/`, 25 с по готовому кешу. Все таблицы — в `summary.md` (перезаписывается при запуске, поэтому выводы здесь). Графики `fig_h1_*.png`, `fig_h2_*.png`; кривые по d — `curves.csv.gz`; d* — `d_star.csv`; покрытие по зонам d — `coverage_zones.csv`. Цифры ниже — H = 64, L = 512, сила strong, если не сказано иное.

**Как считается** (нормировка и d* ждут согласия, см. `docs/decisions.md`):

- Ошибка окна для кривых по d — MAE медианы, делённая на типичную MAE той же модели на том же ряду в устойчивом режиме, который она прогнозирует. До смены эталон — медиана по окнам `d < −H`, после смены — по окнам `d ≥ 512` (контекст целиком из нового режима), в зоне `−H ≤ d < 0` — смесь по доле горизонта после τ. 1 — как в устойчивом режиме.
- Обычный MASE для кривых по d не годится: его знаменатель (ошибка наивного прогноза по контексту) меняется, пока в контекст входит новый режим. При смене дисперсии MASE в зоне 0 ≤ d < 64 равен 2.83 (до смены 1.09) и «восстанавливается» к d ≈ L, хотя отношение там 0.92: ошибка модели не выросла. При смене AR MASE падает с 1.08 до 0.70 при отношении 1.0. MASE тоже посчитан (`metric = mase` в `curves.csv.gz`).
- Кривая — геометрическое среднее по 10 рядам ячейки. 95% полоса — бутстреп по рядам целиком, так как окна одного ряда зависимы.
- d* — первое d ≥ 0, начиная с которого сглаженная кривая (среднее по 3 соседним d) не выше порога вплоть до d = 504. Порог 1.25, а не 1.1 из плана: при 1.1 контроль без изменений даёт ложные d* до 352. Кривая контроля при d ≥ 0 доходит до 1.36 при H = 16 и до 1.19 при H = 64.

**H2 подтверждается.** Глобальное покрытие 80%-интервала по всем окнам — 0.79 (H = 16) и 0.81 (H = 64), до смены — 0.81 и 0.84. В зоне 0 ≤ d < 64 у класса change покрытие 0.72 при обоих H. Хуже всего frequency (0.51), trend (0.53), variance (0.56). Минимум по d — 0.26 у freeze (d = 120, конец залипания) и 0.34 у sensor_bias (d = −8, смена в горизонте); у контроля минимум 0.79 (при H = 16 — 0.66). Причины разные (в скобках — во сколько раз ошибка и ширина интервала при 0 ≤ d < 64 больше, чем в устойчивом новом режиме):

- variance: медиана не хуже (ошибка × 0.92), но интервал вдвое уже нужного (× 0.52). Покрытие возвращается к 0.79 только при 128 ≤ d < 256.
- frequency и trend (strong и medium): ошибка × 1.2–1.8, ширина × 0.67–0.81. Интервал переуверен.
- mean и sensor_bias: ошибка × 1.4–1.5, ширина × 1.2–1.3. Интервал расширяется, но меньше, чем растёт ошибка.

**H1 подтверждается частично.**

- Резкие смены уровня (mean, sensor_bias, амплитуда сезонности) и выброс: пик 1.5–2.5× сразу у точки смены (d = 0–8). Такой же пик при смене в горизонте: mean 2.25, sensor_bias 2.50 при d = −8. Восстановление быстрое: d* = 16–72, далеко не дожидаясь вытеснения старого режима (L = 512). От L d* почти не зависит: sensor_bias 48 / 96 / 56 / 72 при L = 64 / 128 / 256 / 512, исключение — mean при L = 256 (224).
- Частота (смена и дрейф) и тренд: пик позже, 1.6–2.2× при d ≈ 40–120; d* = 216–336. У частоты d* растёт с L: 0 / 24 / 136 / 264 при L = 64 / 128 / 256 / 512, то есть примерно L/2. Похоже на context inertia: пока старый период занимает большую часть контекста, модель его держит. У тренда зависимость от L неясная: 0 / 376 / 240 / 248.
- variance и ar: пик ≤ 1.15, d* = 0. Переход медиану не портит, хотя у variance ошибка в новом режиме втрое выше старого. Провал variance виден только в покрытии.
- Слабые (weak) смены в основном неотличимы от контроля.
- freeze: пока горизонт внутри залипания, ошибка ниже нормы (0.63). Когда залипание кончается, пик 1.9× (d = 120 при длине 128). На коротком контексте аномалии вредят сильнее: spike 5.7× при L = 64 против 2.5× при L = 512.
- Следствие для формулировки H1. «Максимум при малых d > 0» верно для резких смен, но смена в горизонте так же опасна; у частоты и тренда максимум позже. d* сравнимо с L только у частоты.

**Ограничения и следствия для этапа 4:**

- 10 рядов на ячейку мало: 95% интервал d* часто [0; ≥512]. d* по отдельным ячейкам — ориентир. Для твёрдых выводов нужно больше рядов (30 на ячейку — около 3 ч кеша Bolt) или объединение по силам.
- При H = 16 кривые шумнее: контроль доходит до 1.36.
- Смена в горизонте так же опасна, как d ≥ 0, но по контексту непредсказуема. AURC на этапе 4 считать и по всем окнам, и без зоны `−H ≤ d < 0`.
- Ширина интервала растёт меньше ошибки, а при смене частоты и тренда остаётся ниже уровня нового режима. Значит, S1 (ширина интервала), вероятно, слаб именно там, где падает покрытие. На этапе 4 подтвердилось (таблица отклика — `docs/results/stage4_signals.md`), но по всем окнам S1 оказался самым сильным сигналом.

## Пересчёт по утверждённому протоколу v1 (2026-11-12)

Новые таблицы и графики сохранены отдельно от исторических: `results/protocol_h1_h3_v1/stage3/<модель>/`. Полный протокол — `docs/protocol_h1_h3.md`; расчёт использовал только кеш прогнозов, без инференса. Общая реализация относительной MAE находится в `src/evaluation.py`, а межэтапная сверка — в `results/protocol_h1_h3_v1/validation.json`.

- Для Bolt-small при H = 64 и L = 512 порог Q95 равен 1.046; глобальное покрытие 80%-интервала — 0.812, у смен в зоне 0 ≤ d < 64 — 0.721. Для Chronos-2 порог равен 1.021, покрытие — 0.780 и 0.662 соответственно. Это сохраняет вывод H2 о плохом условном покрытии при близком к номиналу глобальном.
- При Q95 у Bolt для сильной смены среднего сглаженный пик относительной MAE равен 1.90 при d = 0, а для сильных частоты и тренда — 1.72 при d = 16 и 2.22 при d = 80; точечные d* равны 400, 312 и 416. Для Chronos-2 соответствующие пики 2.18, 2.48 и 2.93; d* равны «не подтверждено», 408 и «не подтверждено».
- Картина зависит от типа изменения и модели: для смены дисперсии пик у Bolt равен 1.04 (статус `no_degradation`), у Chronos-2 — 1.07 и d* = 112; сильные сезональные смены дают d* = 168 и 192. Это поддерживает только качественную, типо-зависимую часть H1, а не единую форму восстановления.
- d* остаётся неустойчивым при 10 рядах на ячейку: у части ячеек статус `not_confirmed`, а условные интервалы по recovered-бутстрепам часто широки. `not_confirmed` не трактуется как d* ≥ 512. Drift сохранён с оговоркой о приближённом эталоне 512–640; рядом в файлах есть анализ без drift.
- Эти числа — уточнённый пересчёт уже изученной синтетики, а не независимая валидация. При необходимости увеличивать число рядов следует адресно для ячеек с неустойчивым d*, как записано в протоколе.

## Этап 3: H1 и H2 на chronos-2 (2026-11-01)

`python -m scripts.stage3_failures --model amazon/chronos-2` → `results/stage3/chronos-2/`, 24 с по кешу. Скрипт и определения те же, что у Bolt. Цифры — H = 64, L = 512, сила strong, если не сказано иное; в скобках — Bolt.

- **Порог d*.** Правило скрипта («наименьший порог, при котором у контроля нет ложных d*») дало Chronos-2 порог 1.1 при H = 64: контроль у него тише (максимум 1.13 против 1.19 у Bolt). При H = 16 порог 1.25. Поэтому основная таблица d* в `summary.md` при H = 64 построена с порогом 1.1. Ниже обе модели сравниваются при одном пороге 1.25 (`d_star.csv`, `threshold = 1.25`). Какой порог брать, решается вместе с определением d* (`docs/decisions.md`, «Ждёт согласия»).

**H2 подтверждается и на Chronos-2.** Глобальное покрытие 80%-интервала — 0.77 при H = 16 и 0.78 при H = 64 (0.79 и 0.81); до смены 0.78 и 0.79 (0.81 и 0.84). В зоне 0 ≤ d < 64 у класса change — 0.68 и 0.66 (0.72). Хуже всего trend 0.41 (0.53), frequency 0.48 (0.51), variance 0.59 (0.56), mean 0.60 (0.75). Минимум по d: sensor_bias 0.28 при d = −8 (0.34); mean, trend и freeze 0.30 при d = 0, 72 и 120. У контроля минимум 0.74 (0.79). Причины, как и у Bolt, разные (ошибка × / ширина × при 0 ≤ d < 64 к устойчивому новому режиму):

- variance: 0.94 / 0.61 (0.92 / 0.52). Медиана не хуже, интервал слишком узкий.
- trend: 2.15 / 0.97 (1.78 / 0.67). Интервал не расширяется.
- frequency: 2.33 / 1.29 (1.58 / 0.79). В отличие от Bolt, Chronos-2 при смене частоты интервал расширяет, но намного меньше, чем растёт ошибка.
- mean и sensor_bias: 1.68 / 1.17 и 1.65 / 1.32 (1.42 / 1.22 и 1.54 / 1.27).

**H1: картина та же, что у Bolt, с отличиями** (порог 1.25):

- Резкие смены уровня и сезонности: пик сразу у точки смены, как у Bolt: mean 2.32, sensor_bias 2.50, seasonality 1.59 (2.13, 2.31, 1.49). Смена в горизонте так же опасна: 2.28, 2.59, 1.65.
- Восстановление после смены уровня медленнее. Сглаженная кривая выше 1.25 до d = 120 у mean и до d = 80 у sensor_bias (у Bolt до 32 и 72). В таблице у обеих смен d* = 336, но это дала одна точка при d = 328, где сглаженная кривая чуть выше 1.25; без неё d* было бы 128 и 88. При 10 рядах на ячейку d* в текущем определении неустойчив: один поздний выброс сдвигает его на сотни точек.
- frequency: пик выше и раньше, 2.56 при d = 16 (1.77 при d = 104); при смене в горизонте 1.97 (1.37). d* растёт с L, как у Bolt: 40 / 88 / 152 / 224 при L = 64 / 128 / 256 / 512 (0 / 24 / 136 / 264). Признак context inertia сохраняется. У дрейфа частоты так же: 136 / 184 / 264 / 312.
- trend: пик 2.99 при d = 80 (2.23 при d = 88), d* 312 (248).
- variance и ar: пик ≤ 1.08, d* = 0, как у Bolt.
- Выброс вредит Chronos-2 сильнее при длинном контексте, у Bolt наоборот: пик 5.39 при L = 512 и 3.23 при L = 64 (2.45 и 5.65); при H = 16 — 10.68 и 6.33 (4.54 и 8.58). Восстанавливаются обе быстро: d* = 16 при H = 64.
- freeze — как у Bolt: пик 1.88 при d = 120, d* 136.
- Обычный MASE даёт тот же артефакт, что у Bolt: при смене дисперсии MASE при 0 ≤ d < 64 равен 2.86, а отношение к устойчивому режиму 0.94.

**Следствия:**

- Выводы этапа 3 переносятся на вторую архитектуру. Глобальная калибровка хорошая, но условное покрытие в переходе падает до 0.66. Резкие смены опасны сразу у точки смены и при смене в горизонте; у частоты d* растёт с L.
- Chronos-2 при смене частоты расширяет интервал (× 1.29), а Bolt его сужает. Значит, на Chronos-2 S1 может сильнее реагировать на такие переходы. Проверит этап 4.
- Ограничения те же, что у Bolt: 10 рядов на ячейку, широкие интервалы d*. Неустойчивость d* к одной поздней точке — довод при согласовании его определения (например, требовать, чтобы кривая была ниже порога на доле d, а не на всех d). Определение не менял.
