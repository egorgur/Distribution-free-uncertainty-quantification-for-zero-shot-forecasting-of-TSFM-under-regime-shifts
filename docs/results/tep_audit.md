## 1. Источник и две разные версии TEP

Скачан [архив MIT](https://web.mit.edu/braatzgroup/TE_process.zip), на который
ссылается [страница группы Braatz](https://web.mit.edu/braatzgroup/links.html).
ZIP — **4 925 905 байт**, 48 файлов: 44 числовые таблицы, README и три текста
Fortran. Архив и оригиналы находятся в `data/raw/tep_mit/`; большие копии
исключены из Git, SHA256/размеры/CRC — в `manifest.json`. Все извлечённые
байты сверены с ZIP, полный CRC пройден. Скачанный Fortran **не исполнялся**.
Условия использования сохранены в оригинальном README внутри архива.

Это **симуляция химического процесса**, не физические промышленные измерения.
Здесь 22 сценария (normal и fault1…21), по одному train- и test-файлу каждого.
Это не 500 независимых повторов каждого сценария.

Не смешивать с [Rieth et al.2017, DOI10.7910/DVN/6C3JR1](https://doi.org/10.7910/DVN/6C3JR1):
по [первичной метадате](https://dataverse.harvard.edu/api/datasets/:persistentId/?persistentId=doi:10.7910/DVN/6C3JR1)
там четыре RData, fault0…20, simulationRun1…500, 55столбцов, train500/test960
отсчётов, разные seed train/test; вмешательство после1/8ч соответственно.
Четыре RData **не скачаны и численно не аудированы** в этой работе. Сведения
о 500 повторах — документальные, не результат проверки MIT-таблиц. Номер
fault в Rieth — тип сценария всего запуска, не поточечная метка состояния.

## 2. Фактические длины, формат и частота

| Файлы MIT | Число | Отсчётов на файл | Число переменных |
|---|---:|---:|---:|
| `d00.dat` |1|**500**|52|
| `d01.dat`…`d21.dat` |21|480|52|
| `d00_te.dat`…`d21_te.dat` |22|960|52|

Всего **31 700 многомерных отсчётов**, 1 648 400 чисел; NaN/Inf нет.
Особенность оригинала: `d00.dat` — **52 строки×500 столбцов**, остальные
таблицы — время×52. Он транспонируется только при чтении; оригинал не меняется.
README обобщает train как480×52, но фактический normal-файл этому не соответствует.
Строгий парсер проверяет длину каждой физической строки, не дополняет её NaN.

Состав52переменных по README: XMEAS1…41, XMV1…11. Последние — управляющие
величины, а не52независимых датчика/события. Один полностью постоянный
канал×файл: XMV04 в `d21.dat`; это не объявляется повреждением измерения.

**Номинальный шаг180с** задан `temain_mod.f.txt`: `MOD(I,180)`, интегратор1с,
NPTS172800, SSPTS3600×8. В самих DAT нет timestamp; отсутствие реальных
пропусков времени по этим таблицам не проверяется. Документированная сетка
соответствует24ч для480отсчётов и48ч для960, а L512 — **25.6ч**, H64 —3.2ч.
XMEAS23…36 обновляются внутри симуляции каждые0.1ч, XMEAS37…41 —0.25ч,
есть задержки измерения: запись всех столбцов каждые3мин не означает их
одинаковую физическую частоту обновления. Повторы концентраций ожидаемы.

## 3. Что означает событие и где τ

Поставленный Fortran описывает disturbances1…7 как step,8…12 как random
variation,13 — slow drift,14…15 — sticking,16…20 — unknown. Для fault21
отдельная проверенная характеристика в этом описании не установлена.
Не объединять всё это в однородный класс мгновенной смены уровня.

В закрытом контуре включение вмешательства может компенсироваться регулятором;
оно не гарантирует постоянный новый уровень, физическую аварию или восстановление
ошибки через одинаковое время. τ вмешательства — не автоматически конец перехода.

Для **диагностики геометрии test fault** использована граница после первых160
отсчётов, индекс160 с нуля, по8ч/180с из поставленного кода. Поточечной
разметки в DAT нет. Порядок OUTPUT/INTGTR у границы допускает вопрос о первом
затронутом отсчёте159/160; перед прогнозным протоколом его нужно явно решить
или зафиксировать чувствительность. Геометрический вывод для L512 от сдвига
на одну точку не меняется. Для train onset по имени файла **не выдумывался**:
нет сохранённой истории параметров каждого запуска, а код — пример fault12.

## 4. Rolling-окна и эталон

Сетка в каждом файле `t=L−1+8k`, цель `t+1…t+H`, без склейки файлов.
Таблица считает **многоканальные окна**, не умножает их на52.

| Выборка | L512/H64 | L128/H16 |
|---|---:|---:|
| Все train-файлы |0|948|
| Все test-файлы |1078|2266|
| На один test-файл |49|103|
| До вмешательства в одном test fault |**0**|**3**|
| Вмешательство в горизонте |**0**|2|
| Смесь в контексте |20|15|
| Полный послесменный контекст |29|83|

Последние четыре строки — условная геометрия при τ160, **не** свидетельство
стационарности послесменного участка. Для L512 первое t511, **d351**;
последнее d735. Пик непосредственно околоτ уже пропущен. Выдать позднюю
кривую за полную проверку H1/d* нельзя. При L128 геометрия события доступна,
но предсменный эталон по трём сильно перекрывающимся окнам крайне ограничен,
а это уже другая конфигурация S4 и горизонта, не прежний основной протокол.
Присоединение normal/train к test для удлинения истории запрещено без
доказанной непрерывности.

Поздняя динамика описана отношением разности средних половин последних128
строк к их std, без порога отбора: медиана0.274, Q95=1.254 по определённым
канал×файл значениям;37отношений не определены при нулевой std. Эта диагностика
не проверка стационарности, не критерий включения и не доказательство
устойчивого эталона MAE. Полностью послесменный контекст сам по себе недостаточен.

## 5. Независимость и zero-shot

MIT даёт **21 тестовый fault-сценарий**, а не подтверждённое число независимых
повторов. Совпадают первые160полных52-мерных отсчётов у `d04_te.dat` и
`d05_te.dat`. Во всех946парах44таблиц проверены точные совпадения по одинаковому
номеру строки; только эта пара имеет совпадения, общий префикс160. Проверка
не исключает зависимости seed или совпадений с другими временными сдвигами.
Описание Fortran требует менять seed вручную; seed каждого архивного запуска
не сохранён в числовых файлах. Bootstrap по всем52каналам или rolling-окнам
как независимым наблюдениям некорректен.

По [официальному ответу maintainer Chronos](https://github.com/amazon-science/chronos-forecasting/discussions/246)
реальный корпус Bolt совпадает с Chronos, и не перечисленные наборы не
использовались. Tennessee Eastman отсутствует в [полном перечне Chronos v2,
AppendixB/Table2](https://arxiv.org/html/2403.07815v2#A2). Это документальное
основание исключения TEP из названного реального корпуса, не независимый
побайтовый аудит всего предобучения/синтетики и не автоматический вывод
для любой другой модели.

## Вывод

TEP полезен как **дополнительный симуляционный** набор. Для первого
подтверждения на физическом процессе его выбирать нельзя; при L512 не видна
окрестность события. Ни уменьшение L, ни расширенный Rieth не делают его
натурными измерениями. Протокол/инференс H1–H3 на нём не запущены.
