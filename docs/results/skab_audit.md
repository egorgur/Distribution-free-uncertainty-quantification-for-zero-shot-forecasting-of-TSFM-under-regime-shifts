## Короткий ответ на пять вопросов

1. **Длина.** 34 размеченных эксперимента по 745–1327 строк (780–1398 с между
   крайними timestamp) и один normal-файл: 9405 строк, 9960 с. Всего 46 806 строк
   и восемь синхронных датчиков; это не 280 независимых рядов.
2. **Частота.** Типичный шаг — 1 с, но регулярной секундной сетки нет:
   2549 интервалов длиннее секунды, максимум 247 с. Максимальный непрерывный
   блок с шагом ровно 1 с — **28 строк**. Поэтому **ни одного строгого окна**
   L+H = 576 или 144 точек нет, даже в normal-файле и даже при любом сдвиге
   начала окна. Отсутствие NaN не решает проблему пропущенных timestamp.
3. **Смысл меток.** 129 положительных CP-меток, но 34 эксперимента и 34 начала
   anomaly=1; CP может означать начало перехода, не только установление нового
   режима. Upstream использует правосторонний допуск детекции 60 с. Допуск
   детекции **не** является универсальной длительностью установления процесса.
4. **Устойчивые до/после.** Не гарантированы. При L512 ни после одного CP до
   следующего CP/конца файла нет 576 строк; максимальная такая длина — 410.
   Даже без требования регулярного времени геометрия прежнего послесменного
   эталона для `mae_ratio` отсутствует. При L128 она менее жёсткая, но физическая
   устойчивость всё равно не следует из постоянства anomaly или отсутствия CP.
5. **Независимость и предобучение.** Не считать независимыми CP, датчики,
   перекрывающиеся окна и даже автоматически все файлы: найдены пять пар файлов
   с **1290 совпадениями timestamp и всех восьми датчиков**. Для Chronos/Bolt
   есть документальное основание считать SKAB не входившим в опубликованный
   корпус; это не независимое доказательство отсутствия любых пересечений и не
   заключение для Chronos-2/TimesFM/Moirai.

**Итог:** SKAB можно рассматривать как небольшой дополнительный промышленный
набор для последующего исследования надёжности/переходов. Но считать его уже
готовым основным реальным подтверждением H1 и d* при L512/H64 нельзя.

## 1. Целостность и схема

Все **38 оригиналов** из `data/raw/skab/manifest.json` проверены по размеру,
SHA256 и Git blob SHA1: **35 CSV + два README + LICENSE**, несовпадений нет.
Git blob считается как SHA1(`blob <число байт>\0` + оригинальные байты).
Сверяется именно зафиксированный локальный манифест с upstream blob ID;
повторного сетевого скачивания в аудиторе нет. Наличие/отсутствие каждого CSV
также сверяется с манифестом. LICENSE — GPL v3.0 по upstream README, оригинал
сохранён; аудит не переопределяет условия распространения данных.

Каждая физическая строка проверяется на число полей; затем проверяются схема,
timestamp и двоичные метки. Во всех CSV восемь датчиков:
`Accelerometer1RMS`, `Accelerometer2RMS`, `Current`, `Pressure`, `Temperature`,
`Thermocouple`, `Voltage`, **`Volume Flow RateRMS`**. Последнее — фактическое
имя столбца, не сокращённое `RateRMS` из upstream README.

В 34 CSV есть `anomaly` и `changepoint`; в
`data/anomaly-free/anomaly-free.csv` **обеих меток нет**. Они не заполняются
нулями: «normal» — описание источника, не наблюдаемая двоичная разметка и не
доказанная стационарность. Восьмиканальные значения NaN/+Inf/−Inf отсутствуют,
целиком постоянных датчиков в отдельных файлах нет (280 проверок файл×датчик).
Есть короткие серии одинаковых показаний: максимум 43 строки у
`Volume Flow RateRMS` в `valve1/4.csv`; это не приравнивается автоматически к отказу.
Диапазоны, std, число уникальных значений и повторов каждого датчика —
`results/skab_audit/columns.csv`.

## 3. Разметка: CP, anomaly, физические эксперименты

По описанию upstream каждый размеченный файл — один эксперимент с одной
коллективной аномалией. Локальный подсчёт согласуется с этим: **34 серии
anomaly=1**, 34 перехода 0→1, 32 перехода 1→0. В `other/1.csv` и `other/4.csv`
аномалия продолжается до конца файла (правое цензурирование).
Всего 66 серий anomaly=0, 24 334 нормальных по метке строки; anomaly=1 —
13 067 строк. Размах длин серий: 0-метка 32–796 строк, 1-метка 188–586 строк.

129 CP распределены так: два файла по 2, три по 3, 29 по 4. Среди CP:

- 34 точно совпадают с началом anomaly=1;
- 32 точно совпадают с возвратом anomaly=0;
- **63 не совпадают с изменением anomaly**;
- 32 лежат на anomaly=0, 97 — на anomaly=1;
- положительных серий CP — 128: у `other/8.csv` два соседних CP-положительных
  наблюдения, поэтому даже число CP=1 и число переходов CP 0→1 различаются.

Для многих дополнительных меток расстояние до ближайшего перехода anomaly
около 60 с, но не для всех. Все точные совпадения и знаковые расстояния в
строках и секундах сохранены: `cp_marks.csv`, `anomaly_transitions.csv`.
При равных расстояниях выбирается первая по порядку строк ближайшая метка.
CP — не число независимых физических вмешательств; фазы одного эксперимента
могут иметь несколько меток, а постоянная anomaly может включать переход.

Upstream [README зафиксированной версии](https://github.com/waico/SKAB/blob/b2c0d46c2971dcbfe71e26087b6d231998bb91c2/README.md),
раздел Proposed Leaderboard, явно указывает начало переходной фазы как CP и
правостороннее окно NAB в 60 секунд. Это **правило оценки детекции**, не
гарантия, что физический процесс стационарен через 60 с.
`data/README.md` описывает закрытие входного/выходного клапана, утечки/долив,
дисбаланс ротора, кавитацию и подачу более горячей воды; типы вмешательств
разнородны. Список имён файлов в этом README местами устарел: для инвентаря
использованы реальные 35 CSV и закреплённый manifest, не нарисованное дерево.

Предыстория **первой anomaly**, не обязательно любого CP: 104–796 строк,
медиана 572; ≥512 строк в 32/34 файлах, ≥128 — в 33/34. До первого начала
аномалии это ещё не означает 512 непрерывных секунд, физически устойчивый
контекст или отсутствие более раннего CP. Поля `prehistory_rows` и
`contiguous_prehistory_rows` различаются намеренно.

## 4. Геометрия соседних CP и окон

Индексы с нуля. CP в строке `c` считается первой строкой правого сегмента:
левый `[previous_CP,c)`, правый `[c,next_CP)`. Для первого/последнего CP
граница — начало/конец **того же** файла, с флагом цензурирования.
Файлы не склеиваются. 163 CP-сегмента в 34 размеченных файлах, длины
1–796 строк (Q25=57, медиана=171, Q75=288). Normal-файл представлен отдельно
как один неразмеченный отрезок, а не как сегмент с наблюдаемыми CP=0.

| Геометрическое условие у CP | L512/H64 | L128/H16 |
|---|---:|---:|
| До CP в предыдущем сегменте ≥L строк | 32 | 67 |
| После CP до соседней границы ≥H строк | 68 | 123 |
| После CP ≥L+H строк | **0** | 63 |
| Одновременно ≥L до и ≥H после | 4 CP / 4 файла | 61 CP / 33 файла |
| Одновременно ≥L до и ≥L+H после | **0** | 5 CP / 3 файла |
| Те же два совместных условия + непрерывность 1 с | **0 / 0** | **0 / 0** |

Для 512/64 четыре CP с достаточными L до и H после:
`other/12.csv:c568`, `other/5.csv:c572`, `other/7.csv:c572`,
`valve1/2.csv:c566`. **Ни у одного нет позднего полного послесменного окна
512+64 до следующей границы.** При 128/16 совместное условие L до и L+H после
есть только в `other/10.csv:c946,c1156`, `other/5.csv:c572,c982`,
`valve1/2.csv:c566`. Это проверка длины, не отбор «хороших» событий и не
подтверждение устойчивости. Подробности всех 129×2 конфигураций —
`event_geometry.csv`; суммы — `geometry_totals.csv`.

### Rolling origin: точный счёт

В каждом файле сетка **t=L−1+8k**, `k≥0`, `t+H<n`.
Контекст `[t−L+1,t]`, цель `[t+1,t+H]`. Всего L+H строк. Сетка не
перезапускается после CP/разрыва/начала сегмента. `strict_1s` требует ровно
1 с **во всех L+H−1 интервалах**, включая стык контекст–цель и конец цели.
CP в первой строке объединённого окна допустим для одного CP-сегмента;
CP в любой последующей строке объединения — нет.

| Набор / условие | L512/H64 | L128/H16 |
|---|---:|---:|
| Все 35 файлов, порядок строк | **3351** | **5241** |
| 34 размеченных файла, порядок строк | 2247 | 4083 |
| Normal-файл без наблюдаемых меток | 1104 | 1158 |
| Один CP-сегмент, только размеченные файлы | **31** | **2509** |
| Весь контекст и цель внутри anomaly=0 | **31** | **1916** |
| Оба предыдущих ограничения одновременно | 31 | 1916 |
| Любая строка таблицы с требованием strict_1s | **0** | **0** |

При L512 все 31 CP-чистое окно также anomaly=0: 28 из `other/4.csv`, по одному
из `valve1/5.csv`, `valve1/6.csv`, `valve1/7.csv`. CP-чистых окон с anomaly=1
нет. При L128 разница 2509−1916=593 — CP-чистые окна, не целиком anomaly=0;
они не объявляются установившимся новым режимом.

Для normal-файла условные счётчики `same_cp`/`anomaly0` не применимы:
в агрегатах он даёт нулевой вклад, но это **не** нулевое число потенциальных
контрольных окон. В подробной `windows.csv` соответствующие флаги остаются
пустыми. `window_counts.csv` — каждый файл×конфигурация, `window_totals.csv`
— три явно разделённых набора. Числа — **многоканальные временные окна**,
не умножены на восемь и не называются независимыми наблюдениями.

## 5. Почему отсутствие CP не доказывает устойчивость

Фиксированная описательная проверка: в каждом CP-сегменте длиной ≥128 взять
последние 128 строк, разделить на первые/последние 64 и вычислить
`abs(mean(last64)−mean(first64))/std(last128)`, std с ddof=0.
Для normal — хвост всего файла. Никакого порога, p-value или фильтра устойчивости.
При постоянном/неполном численно хвосте отношение не определялось бы; в этих
данных таких хвостов нет. Это **128 строк**, не гарантированные 128 секунд.

Получено 784 значения: восемь датчиков × 98 сегментов (97 размеченных + normal).
Медианы отношения: температура двигателя 0.829, температура жидкости
1.207; остальные датчики 0.128–0.312. Максимумы: Temperature 1.836,
Thermocouple 1.832. Это описательная внутрисегментная динамика; она показывает,
почему опасно автоматически называть хвост установившимся, но не заменяет
статистический/физический анализ стационарности. Все величины — `tail128.csv`.

Четыре иллюстрации заранее выбраны по именам normal, `other/1.csv`,
`valve1/0.csv`, `valve2/0.csv`, не по результатам прогнозирования. Показаны
четыре канала, anomaly и CP; ось — настоящее прошедшее время, серые полосы —
разрывы, линии датчиков через разрывы не соединяются. На normal виден дрейф
температуры жидкости, на клапанных примерах — переходы и последующая динамика.
Графики просмотрены; сами по себе они не доказывают устойчивость остальных
каналов/файлов. Пути: `results/skab_audit/fig_*.png`.

## 6. Независимость: межфайловые дубликаты

Аудит не склеивает файлы. Только для проверки зависимости сделано соединение
пар по timestamp и точное сравнение всех восьми исходных чисел:

| Пара файлов | Общих timestamp = совпадений всех 8 датчиков | Из них разных anomaly |
|---|---:|---:|
| normal / other/5 | **572** | меток normal нет |
| other/10 / other/11 | 21 | 0 |
| other/12 / other/13 | **349** | **178** |
| other/2 / other/3 | 120 | 0 |
| other/3 / other/4 | **228** | **57** |

Всего **1290 точных межфайловых совпадений timestamp+8 датчиков**, 235
различий anomaly на одинаковых показаниях в двух размеченных парах.
Это не обязательно ошибка источника: контекст аномальности может относиться
к конкретному эксперименту. Но глобальная интерпретация anomaly как единой
физической переменной и случайное разделение окон на train/test некорректны.
Normal не полностью независим даже от одного размеченного файла.

34 файла — 34 описанных эксперимента, **не доказанные 34 независимые
реализации**; 129 CP нельзя использовать как 129 независимых событий.
Учитывать также общую установку, одну сессию/дату и синхронные каналы.
При будущем разбиении все связанные копии/каналы/фазы должны оставаться
в одной группе либо пересечение должно исключаться по заранее принятому
правилу. Это необходимое следствие аудита, а не выбранный здесь split.
Числа и временные границы пар — `cross_file_overlaps.csv`.

## 8. Следствия для будущего протокола H1–H3 (не выбор протокола)

- **H1 / `mae_ratio`.** Требуется ошибка той же модели на устойчивом режиме
  того же ряда. При L512 нет даже геометрического послесменного окна 576 строк
  до следующего CP; 31 доступное CP-чистое окно относится только к anomaly=0
  в четырёх файлах. Нельзя выдавать их или normal-файл за автоматически
  подходящий эталон нового режима каждого эксперимента. При L128 ситуация
  лучше по длине, но смысл режима, устойчивость и перенос эталона остаются
  открытыми. Отсутствие эталона нельзя молча исправлять нормировкой на std/MASE.
- **d*.** Отсчёт от неоднозначной CP-метки, повторный CP, обрезанный конец
  записи и нерегулярное время не позволяют просто перенести синтетическую
  процедуру. Нет подтверждения восстановления не равно d*≥L. Секунды и
  индексы строк при этом различаются; 60-секундный NAB-допуск не исправляет
  определения восстановления/устойчивого режима.
- **H2/H3.** Оценка покрытия и ранжирования ошибок возможна как отдельный
  будущий пилот после принятия временной сетки, правил меток/контроля,
  эталона и группового разбиения. Эта работа **не** вычисляет S1/S4, AURC,
  модельную MAE или coverage и не утверждает перенос преимущества сигналов.
- **Временная сетка.** Порядок строк — честная диагностическая альтернативная
  геометрия, не регулярная сетка 1 Гц. Нужны отдельно согласованные правила
  причинной обработки пропусков/масок/ресемплинга; интерполяция будущими точками
  может дать утечку. Просто исключить разрывы при этих L/H означает исключить
  вообще все окна. Автоматически менять L/H по этим результатам нельзя.
- **Объём и независимость.** Для интервалов/сравнений не бутстрепить отдельные
  окна или каналы как независимые. Минимально учитывать эксперимент/сессию и
  найденные связи файлов. Normal как контроль также требует исключения
  пересечения с other/5 по принятому правилу. Результаты геометрии не являются
  мощностью статистического теста и не подтверждают 34 независимых события.
