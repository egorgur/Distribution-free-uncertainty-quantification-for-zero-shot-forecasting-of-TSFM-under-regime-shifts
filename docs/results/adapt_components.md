# Regime-Component Adaptation (H9): реакция на изменившуюся компоненту

Дата расчёта: 2026-11-18. Протокол — [docs/protocol_v3_component.md](../protocol_v3_component.md) v1, согласован до расчёта (`docs/decisions.md`, 2026-11-18). Таблицы — `results/adapt_components_v1/<модель>/H<H>/summary.md`, CSV и `detector_confusion.csv`. Нового инференса нет: реакции из кеша и прогнозов H8.

**Статус выводов: разведка** на synth_v1 seed 0. Результаты H8 на этих данных были видны до протокола, поэтому основной вариант следует инструкции; варианты «после H8» описательные.

## Главное

**H9 по основному критерию не подтверждается ни в одной из 4 конфигураций.** Специализированная реакция при известном типе смены (comp_oracle) не лучше единой стратегии «всегда сдвиг уровня» (uni_level). Причина не в идее специализации вообще, а в отдельных реакциях: короткий контекст для смены сезонности даёт −18…−24%, подгонка масштаба для смены дисперсии не помогает. Там, где реакция подходит (уровень → mean/sensor_bias, тренд → trend, у Chronos-2 короткий → frequency), специализация полезна.

**Практический метод comp_detected** вредит: TG64 от −2.2% до −4.4%, SH на none 4–8%. Правило срабатывает на 17.6% окон рядов без смены и в первые 64 точки после смены чаще всего не видит изменения.

## Основной критерий (change, 0 ≤ d < 64)

MAE(comp_oracle) / MAE(лучшей единой стратегии); меньше 1 — специализация лучше. Лучшей единой во всех конфигурациях оказалась uni_level.

| конфигурация | отношение [95%] | критерий |
| --- | --- | --- |
| **Bolt H64 (основная)** | 1.018 [1.000; 1.038] | не выполнен |
| Bolt H16 | 1.029 [1.014; 1.046] | не выполнен |
| Chronos-2 H64 | 1.002 [0.978; 1.026] | не выполнен |
| Chronos-2 H16 | 1.001 [0.982; 1.021] | не выполнен |

Интервалы по типам — в `summary.md` (30 рядов на тип, 10 на ячейку).

Итог по H9 как исследовательскому утверждению: **частично** — тип адаптации действительно должен зависеть от типа смены (AR и сезонность требуют «ничего не делать», уровень и тренд — своих поправок), но предписанное отображение для дисперсии и сезонности неверно, и в сумме специализация по инструкции не выигрывает у одного сдвига уровня. Перестраивать отображение по этим же данным нельзя — это была бы подгонка; только по новому протоколу на новых данных.

## Определение компоненты (Detected)

Пороги (Q95 none seed 1; считаются по сырым рядам и от модели не зависят): level 0.728, scale 0.407, trend 1.888, freq 0.194.

- На none seed 0 адаптация включается в **17.6%** окон (четыре компоненты по ≈ 5%).
- В 0 ≤ d < 64 правило чаще всего говорит «нет изменения»: mean 71%, trend 83%, frequency 78%, ar 89% окон. Правильная компонента — редко: level для mean 12%, для sensor_bias 22%; trend для trend 5%.
- В 64 ≤ d < 128, когда недавние 64 точки целиком из нового режима, лучше: level для mean 38%, для sensor_bias 51%; но смену тренда правило в половине окон принимает за сдвиг уровня (50%).
- Разложение (Bolt H64, MAE-отношение): знание типа при том же моменте вмешательства (comp_oracle_type / comp_detected) — 0.966 [0.953; 0.981], то есть ошибки распознавания стоят ≈ 3.4% (Chronos-2 H64: 5.1%). comp_detected лучше выбора по ошибке «назад» из H8 (0.981), но всё равно хуже Full.

## Ограничения

- Только seed 0; пороги с seed 1; 10 рядов на ячейку.
- Статистики на 64 недавних точках при периодах сезонности до 48 шумные; правило и пороги не подбирались.
- Oracle знает факт смены в контексте, но не τ: разбиение W = 64 то же, что у практических методов.
- comp_oracle хуже comp_oracle_type (1.015): вмешательство во всех окнах со сменой в контексте включает вредные реакции чаще, чем при срабатывании правила.

## Что это значит

1. Три направления подряд (H7–H9) не дали практического метода без вреда. Общий узкий момент — **распознавание** по наблюдаемому контексту: и ошибка «назад», и статистики компонент слишком шумны в первые 64 точки.
2. Полезные пары «тип → реакция» есть (level для уровня/смещения, тренд с частичной силой, No Adaptation для AR и сезонности); их стоит проверить **заново на новых данных** с заранее исправленным отображением — это отдельное решение с научруком.
3. Направление 4 (интервалы) остаётся непроверенным и не зависит от распознавания типа.
