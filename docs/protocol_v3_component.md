# Протокол Regime-Component Adaptation (H9), версия 1

Дата: 2026-11-18. **Статус: зафиксировано до расчёта.** Предложено ассистентом, согласовано пользователем 2026-11-18 («Согласую H9, продолжи»): AR → No Adaptation, основной вариант по инструкции, критерий по MAE; WIS и покрытие (в том числе для смены дисперсии) — описательно. Основа оценки — как в [Multi-Context](protocol_v3_multicontext.md) (общий эталон Full L512, TG/SH, WIS, покрытие, d*, бутстреп по рядам); преобразования — из [Regime-Aligned](protocol_v3_aligned.md) (W = 64, level/scale/trend). Выводы на synth_v1 — разведочные.

**Важная оговорка о честности.** Результаты H8 на seed 0 уже видны: полная коррекция тренда в среднем вредна, α = 0.5 для тренда выглядела лучше, scale не помогла смене дисперсии. Чтобы не подгонять H9 под эти цифры, основной вариант следует **инструкции дословно** (полные преобразования, отображение «компонента → реакция» из инструкции). Варианты, подсказанные результатами H8, помечаются «после H8» и в критерий не входят.

## 1. Идея простыми словами

Сначала по наблюдаемому контексту определить, **что** изменилось: уровень, разброс, тренд или периодичность. Затем применить к старой истории только подходящую поправку. Если признаков смены нет — ничего не делать (No Adaptation). Чтобы разделить две причины возможной неудачи, сравниваются: реакция при **известном** типе смены (Oracle) и при **определённом по данным** (Detected).

## 2. Данные

- Статистики компонент — без модели, по сырым рядам: пороги по рядам **none seed 1**, оценка на **seed 0**.
- Прогнозы — **без нового инференса**: Full/L64/L128 — основной кеш; level/scale/trend (α = 1 и α = 0.5) — кеш `aligned_v1` из H8; обрезка по τ — `cascade.npz`; mix_hind и sel_align — результаты H7/H8.
- Конфигурации: основная Bolt H64; дополнительно Bolt H16, Chronos-2 H64/H16. Окна pos ≥ −112.

## 3. Определение изменившейся компоненты (Detected)

Разбиение то же, что в H8: O — первые 448 точек контекста L512, R — последние 64. Масштаб старой части m = MAD(O); если m < 1e-3 · s(t), используется s(t) (наивный масштаб контекста).

| Компонента | Статистика z | Смысл |
| --- | --- | --- |
| Level | \|med(R) − med(O)\| / m | сдвиг уровня в единицах разброса старой части |
| Scale | \|log(MAD(R) / MAD(O))\|; при MAD < 1e-3 · s(t) — 0 | во сколько раз изменился разброс |
| Trend | \|b_R − b_O\| · 64 / m, b — МНК-наклоны O и R | на сколько изменился прирост за 64 шага |
| Frequency/Seasonality | среднее \|ρ_O(k) − ρ_R(k)\| по лагам k = 1…24, ρ — выборочная автокорреляция; если std(O) или std(R) < 1e-3 · s(t) — 0 | изменение периодической структуры |

**Пороги:** θ_c — 95-й процентиль z_c по всем окнам оценки рядов none seed 1 (≈ 5% ложных срабатываний на компоненту; общий уровень ложных тревог выше и записывается на seed 0).

**Правило:** сработавшие компоненты — z_c > θ_c. Ни одной → **No Adaptation**. Несколько → компонента с наибольшим z_c / θ_c. Если s(t) = 0 (весь контекст постоянен), все z = 0 → No Adaptation. Правило фиксировано; IQR и std, упомянутые в инструкции, — только в описании, не в правиле.

## 5. Методы

| Код | Тип | Момент вмешательства | Роль |
| --- | --- | --- | --- |
| **comp_detected** | по правилу разд. 3 | по правилу | практический метод |
| comp_oracle_type | **истинный** тип → реакция | по правилу (сработала хоть одна компонента) | цена ошибок распознавания типа при том же моменте |
| **comp_oracle** | **истинный** тип → реакция | **истинный**: окна с 0 ≤ d < L − 1 (смена в контексте); иначе Full | верхний ориентир специализации |
| uni_{level, scale, trend, short} | одна реакция для всех типов | истинный, как у comp_oracle | **единая стратегия** для сравнения |
| full, L64, oracle_trim, sel_align (H8), mix_hind (H7) | сравнения | | |

Отображение истинного типа: mean, sensor_bias, drift-mean → Level; variance → Scale; trend → Trend; seasonality, frequency, drift-frequency → Frequency/Seasonality; **ar, none, anomaly → No Adaptation** (AR не сводится к четырём компонентам; задано до расчёта).

Oracle-привилегии: comp_oracle знает тип и факт смены в контексте, но **не** τ, силу и новые параметры — разбиение остаётся W = 64.

## 6. Критерии

**H9, основной (Bolt H64, seed 0):** на change-окнах 0 ≤ d < 64 парное геометрическое среднее MAE(comp_oracle) / MAE(лучшей единой стратегии) < 1, верхняя граница 95% интервала < 1. «Лучшая единая» — та из uni_{level, scale, trend, short}, у которой на тех же окнах наименьшая средняя log-ошибка (выбрана на тех же данных — это в пользу единой стратегии, то есть консервативно для H9).

**Ожидания H9 по типам (описательно, с интервалами по 10–30 рядам):** level лучше Full при mean и sensor_bias; scale — при variance; trend — при trend. По H8 уже известно, что scale при variance, вероятно, не поможет; это будет отражено как расхождение с H9, а не исправлено.

**Практическая польза comp_detected (дополнительный критерий, в форме H7/H8):** TG64 с нижней границей > 0 и SH на none с верхней границей ≤ 1%.

**Разложение:** comp_oracle vs comp_oracle_type — потери из-за момента вмешательства; comp_oracle_type vs comp_detected — потери из-за распознавания типа (то, о чём просит инструкция: «разница между Oracle и Detected»).

Остальное (H16, Chronos-2, варианты «после H8», покрытие, WIS, d*, матрица ошибок детектора по типам и зонам d, доля No Adaptation на none) — описательно.
