**Статус: утверждён пользователем 2026-11-12 ответом «Принимаю твои предложения», зафиксировано до нового пересчёта.** Приняты все предложенные уточнения, включая численные правила d* и временный приближённый эталон drift с дополнительным анализом без drift. Повторное согласование этих пунктов не требуется. Реализация и пересчёт выполнены после фиксации протокола; результаты и сверка описаны в `docs/results/stage3_failures.md` и `docs/results/stage4_signals.md`. Изменения смысла или численных правил после утверждения требуют отдельной записи и согласования.

## 1. Ошибка и устойчивый эталон

**Принято:** сохранить подход к устойчивым окнам; сравнивать с тем устойчивым режимом того же ряда, который модель должна прогнозировать; типичную ошибку определять медианой. Эталон используется только для оценки, не во входах сигналов.

### 1.1. Устройство текущего расчёта — проверенные факты

`scripts/stage3_failures.py`, `add_ratios`:

- Старый эталон — медиана MAE по `d < −H`.
- Новый эталон для change/drift — медиана MAE по общей поздней полосе `512 ≤ d ≤ 640`.
- Медианы уже вычисляются **отдельно для каждого ряда, модели, L и H**. Короткий контекст не сравнивается с эталонной ошибкой L512.
- Полоса нового эталона общая для всех L; начало полосы не переносится к d = L при коротких контекстах. На сетке с шагом 8 она содержит 17 окон, которые зависимы, а не 17 независимых наблюдений.
- У контроля и временных аномалий эталоном остаётся старый режим на всех d.

### 1.2. Смена внутри горизонта — существующая смесь сохранена

В зоне смены в горизонте `−H ≤ d < 0` использовать

$$b(d)=(1-p)b_{old}+p b_{new},\qquad p=\operatorname{clip}((d+H+1)/H,0,1).$$

Здесь τ — индекс первой точки нового режима, t — последней точки контекста, будущее начинается с t + 1. Поэтому при d = −H в горизонте уже одна точка нового режима; при d = −1 весь горизонт новый. Ошибка окна — MAE / b(d).

Пример: при половине горизонта в каждом режиме и эталонах 1 и 3 знаменатель равен 2. Это соглашение об оценке смешанного горизонта, а не утверждение, что реальная ошибка модели в переходе обязана быть линейной смесью. Эту зону показывать отдельно; H3 дополнительно оценивать без неё.

### 1.3. Отдельные эталоны конфигураций — прежнее правило сохранено

Свой эталон для каждой конфигурации **модель × L × H × ряд**, но одинаковые временные полосы эталона для всех L. Так сравнение d* между длинами не меняет одновременно и длину, и участок эталона.

Если эталон неположителен или нечисловой, отношение не определять; исключение и его количество показывать явно, не подменять знаменатель произвольным epsilon.

### 1.4. Ограничение для дрейфа — принято временное приближение

По `configs/synth_v1.yaml` и `src/synth.py` дрейф длится 128 точек: окончательное значение параметра впервые достигается при d = 127. Для L512 контекст целиком после достижения этого значения только при d ≥ 638; на текущей сетке подходит **одно окно d = 640**. Даже это условие не доказывает полного исчезновения динамического перехода процесса.

Следовательно, полоса 512–640 у drift не является строго полосой контекстов, целиком состоящих из установившегося нового режима. Это ограничение прежнего подхода, не новый результат модели. Нельзя незаметно заменить медиану 17 окон единственным окном или выдать прежний эталон за строго устойчивый.

**Принято для ближайшего пересчёта:** оставить прежнюю полосу как приближение и явно помечать результаты drift; рядом показать анализ без drift. Это не меняет основной набор окон H3 задним числом. Строгий поздний эталон и дополнительные прогнозы для него сейчас не требуются. Если он понадобится в дальнейшем, заранее согласовать дополнительные поздние окна/данные и адресный инференс; весь кеш пересчитывать не нужно.

## 2. Порог естественных колебаний

**Принято:** одинаковые агрегация и сглаживание у контроля и оцениваемой кривой; один основной процентиль и второй для чувствительности; единое правило с отдельными порогами для конфигураций.

**Утверждённая процедура:**

1. Основной процентиль — 95-й; 90-й — проверка чувствительности. Не выбирать основной заново после результатов.
2. Контроль для порога — 10 рядов none seed 1. Отчёт и проверка переноса порога — seed 0. Для каждой модели, L и H считать свой порог, без порогов по типу/силе смены.
3. Для каждого контрольного ряда вычислить MAE / медиану его MAE на `d < −H`, как у контроля seed 0.
4. Геометрически усреднить отношения по 10 рядам; сгладить логарифм кривой средним по трём соседним d. Для порога и d* использовать только сетку 0, 8, …, 504. На краях сглаживать по имеющимся точкам этой области, без привлечения эталонной зоны d ≥ 512.
5. Порог — эмпирический процентиль значений полученной сглаженной кривой по этой сетке (линейная интерполяция процентиля). Если он ниже 1, использовать 1: превышение обычного уровня не должно определяться порогом ниже нормы. Число хранить вместе с конфигурацией и исходным некорректированным процентилем.

Число рядов в групповой кривой контроля и в оцениваемой ячейке сейчас одинаково — 10. При адресном расширении ячеек до 30 необходимо отдельно согласовать сопоставимую оценку контрольной изменчивости, а не бездумно переносить порог для среднего по 10 рядам.

Это эмпирическое правило, **не гарантия 5% ложных обнаружений деградации** на всей кривой. Точки d перекрываются и зависимы; 64 положения d не заменяют 64 независимых контрольных эксперимента. Обе синтетические выборки уже изучались; новый пересчёт не называть полностью независимым подтверждением уточнённой H1.

## 3. Восстановление d*

**Принято:** сочетать минимальную длительность восстановления с ограничениями на поздние превышения. Численные параметры ниже **утверждены пользователем до нового расчёта**. Это рабочий исследовательский критерий, а не стандартный статистический критерий с формальными гарантиями.

Для сглаженной кривой на 0, 8, …, 504:

1. Если превышений порога нет, статус — «заметной деградации по этому правилу не обнаружено». d* не сообщать как наблюдённое время восстановления.
2. Если превышения есть, искать начало восстановления **после максимума сглаженной кривой** на этой области (при равных максимумах — после последнего). Это ретроспективное описание, не онлайн-детектор. Оно не позволяет назвать затишье перед задержанным пиком восстановлением.
3. Начиная с кандидата должны быть **9 последовательных значений не выше порога**. При шаге 8 расстояние между первым и последним — 64 точки времени.
4. На всём остатке от кандидата до d = 504 допускается не более 10% значений выше порога и не более двух подряд. Долю считать по числу доступных значений; порог для целого количества превышений — округление вниз.
5. d* — минимальный кандидат, выполняющий условия. Если подтверждающего участка не хватает или условия не выполнены, статус — «восстановление не подтверждено до конца наблюдения».

Из-за подтверждения длиной 64 последний возможный кандидат на этой сетке — d = 440. Нельзя интерпретировать отсутствие подходящего кандидата как доказательство d* ≥ 512: модель могла восстановиться в самом конце, но времени для подтверждения нет. Это ограничение нужно показать в таблице и при сравнении d* с L.

64 точки выбраны как один основной горизонт H = 64; они одинаковы для H16/H64 и всех L ради сопоставимости. 10% и две точки — прозрачный допуск редких колебаний, не числа, выведенные из теории. Порог 90-го процентиля меняется в анализе чувствительности, остальные правила сохраняются. Прежнее строгое d* можно показать отдельно как дополнительное описание, не выбирая лучший вариант по результатам.

Не смешивать три статуса в бутстрепе: «нет обнаруженной деградации», численное d*, «нет подтверждённого восстановления». Показывать частоты статусов; интервалы численного d* явно называть условными по повторам с численным результатом. Сохранять весь ряд при бутстрепе. Если порог не пересчитывается, интервалы условны на контроле seed 1 и не отражают его неопределённость.

## 4. H3 — выбор в рамках делегированного пункта

Пользователь поручил опираться на предложения ассистента по пункту 4. Для ближайшего **пересчёта синтетики** фиксируется до нового расчёта:

- Основная ошибка — относительная MAE из раздела 1, в H3 для основного контекста L512. Медианы эталонов брать по полной сетке, до исключения первых окон из-за недоступности S2. Реализация и цель ошибки H1/H3 должны быть общими, а не двумя похожими формулами.
- Сигналы и их контекстную нормировку не менять. Эталон будущей ошибки во входах сигналов не использовать. MASE оставить дополнительной исторической метрикой.
- Основные сравниваемые методы — S1, S4б (512/256/128/64, три дополнительных прогона), их прежнее равновесное среднее рангов. Сохранить также бейзлайны и S7 для исходной H3, не выбирать новый лучший вариант.
- Основная конфигурация — Chronos-Bolt-small, H = 64, все прежние окна оценки (`pos ≥ −112`), включая прежний состав классов. Основной отчёт — seed 0; Bolt seed 1 и Chronos-2 seed 0 — дополнительные проверки. Результаты старой синтетики не считать новой независимой валидацией метода.
- Основное сравнение комбинации — парная разность **AURC(комбинация) − AURC(S1)**. Преимущество: верхняя граница 95% интервала парного бутстрепа по рядам (1000 повторов, одинаковые выборки у методов) ниже нуля. Сравнение с S4б также обязательно показать; победой над обоими называть только преимущество над обоими. Выигрыш относительно случайного отказа/оракула — дополнительно; при вырожденном знаменателе его не определять.
- AUROC/AUPRC считать для худших 10% по новой относительной MAE внутри каждого H и оцениваемого набора окон, а не по прежним меткам MASE. Сохранять прежнее правило обработки границы/равных значений и сообщать фактическую долю плохих окон. Спирмен, риск при принятии 80/90% окон и кривые риск–покрытие показывать рядом.
- Дополнительные анализы — H = 16, без зоны смены в горизонте, переходы 0 ≤ d < 128, анализ без drift ввиду раздела 1.4. Не подменять ими основной результат при его неудаче.
- Ранги комбинации считать по всей доступной оцениваемой выборке сигналов того же H до отбора подгрупп, как в прежнем пакетном анализе; при бутстрепе значения комбинированного сигнала фиксированы. Это безметочная **пакетная** оценка: она не доказывает готовность того же правила для одного нового окна онлайн. Онлайн-вариант потребует отдельной фиксации, не добавлять его скрытно сейчас.

Эти решения не изменяют исходную H3 на «комбинация обязательно лучше». Для первого реального датасета критерий и единицы бутстрепа окончательно записать после аудита структуры данных, но **до просмотра сравнительного качества методов**. Наличие выгоды только на старой синтетике недостаточно для назначения комбинации основным методом.
