# Ограниченный аудит реальных экземпляров Petrobras 3W

Дата: 2026-11-18. **Статус: зафиксировано до загрузки.** Предложено ассистентом, согласовано пользователем 2026-11-18 («Да, загружай»). До согласования просмотрены только 13 случайных реальных файлов в scratch (длины периодов, пригодные переменные); эти файлы в аудит не переносятся, всё скачивается заново по закреплённому commit. Это **описательная проверка кандидата**, не прогнозный протокол, не выбор эталона и не экран устойчивости. TSFM не запускаются. Требование устойчивого эталона из протокола H1/H3 v1 не ослабляется.

## 1. Вопрос аудита

Сколько реальных событий 3W дают **документированный** старый режим, документированный новый режим и переход между ними такой длины, что на них можно построить окна по протоколу H1/H3 v1 (старый эталон d < −H, новый эталон L ≤ d ≤ 640) при разумном масштабе времени — и какие переменные в этих событиях вообще пригодны.

## 2. Источник и загрузка

- Репозиторий [petrobras/3W](https://github.com/petrobras/3W), закреплённый commit `c86cc7c70063646910be7292de8a54a6fb2a8399` (2026-11-15), `dataset/dataset.ini`: DATASET = 2.0.0. Лицензия данных CC BY 4.0.
- Загружаются **только реальные экземпляры** (`dataset/<класс>/WELL-*.parquet`): 1119 файлов, 516 МБ по размерам git-объектов; плюс `dataset.ini`, `README.md`, лицензия, полное оглавление дерева. Симулированные (1089) и нарисованные (20) не загружаются.
- Каждый файл скачивается по raw-ссылке закреплённого commit; проверяется git-blob SHA1 из дерева, сохраняются SHA256 и размер. Несовпадение — ошибка, файл не используется.
- Хранение: `data/raw/3w/` (исключено из git), манифест — в git. Чтение Parquet — `pyarrow` (новая зависимость, версия фиксируется в `requirements.txt`).
- Загруженные файлы — недоверенные данные: отдельная папка, скрипты вне неё.

## 3. Определения (до просмотра данных)

- **Периоды** — максимальные подряд идущие наблюдения с одной меткой `class` (как в статье). NaN — «неизвестно».
- **Событие** — экземпляр с переходом: есть период 101–109. **τ (точка смены)** = первое наблюдение первого переходного периода. Старый режим — период 0, непосредственно предшествующий τ; новый режим — период устойчивого состояния события (1–9), следующий за переходом (если есть).
- События без перехода (классы 3 и 4 по статье — сильный слаггинг и неустойчивость потока — не имеют переходных меток) и экземпляры только с меткой 0 учитываются отдельно: первые — описательно, вторые — как **кандидаты стабильного контроля**.
- **Пригодная переменная в периоде** — числовая, не NaN во всех наблюдениях периода и не постоянна (число различных значений > 1). Переменные состояния клапанов `ESTADO-*` (значения 0/0.5/1) учитываются, но не считаются кандидатами для прогноза.
- **Замороженный участок** — ≥ 60 подряд одинаковых значений; доля таких наблюдений по переменной.
- **Признак интерполяции** — доля шагов с |Δ²x| ≤ 1e-9 · (медиана |Δx| по периоду, если она > 0): мера кусочно-линейности из-за интерполяции PI. Только описательно.
- **Масштабы времени:** агрегирование средними по непересекающимся блокам k ∈ {1, 10, 60} с (без перекрытия, NaN-блоки — NaN).
- **Конфигурации окон:** (L, H) ∈ {(512, 64), (128, 16)}.
- **Достаточная длина для события** при масштабе k и (L, H):
  - старый режим ≥ L + 2H точек (полное окно с d < −H и хотя бы H окон старого эталона);
  - переход + новый режим ≥ 640 + H точек от τ **и** новый режим ≥ L + H точек (новый эталон L ≤ d ≤ 640 целиком внутри устойчивого состояния). Если 640 + H больше доступного — отдельно отчитывается доля d-сетки, которая наблюдается.
  Эти пороги — прямой перенос протокола v1; они не подбираются по данным.

## 4. Что считается и сохраняется

1. Оглавление: число файлов по классам и скважинам; сравнение с таблицей статьи (594/4/22/32/343/11/6/36/14/57) и с числом скважин (статья — 42, по дереву — 40).
2. Время: шаг, пропуски, дубли, монотонность; длина экземпляра; совпадение с 1 Hz.
3. Метки: последовательность периодов по каждому файлу; длины 0 / 10x / x / NaN; доля экземпляров со структурой «0 → 10x → x», «0 → 10x», иное; метки `state` в старом и новом режимах.
4. Переменные: пригодность по периодам, NaN, замороженность, признак интерполяции.
5. Пригодность событий: число событий, удовлетворяющих разд. 3, по классу × k × (L, H), с числом пригодных переменных в обоих режимах; число скважин, дающих такие события.
6. Независимость: пересечение/смежность временных интервалов файлов одной скважины; число событий на скважину. Окна одного события и события одной скважины — не независимые повторы.
7. Стабильный контроль: экземпляры класса 0 — длины, пригодные переменные, достаточность для L + H при каждом k.
8. Графики: по одному примеру на класс (выбор — первый по имени файла пригодный экземпляр, не по виду ряда).

## 5. Что аудит не делает

Не выбирает итоговые L/H, масштаб, переменные и эталон; не запускает TSFM; не склеивает экземпляры; не использует симулированные экземпляры как реальные; не трактует неисправности как изменения задания; не подбирает пороги ради большего числа событий. По итогам — отдельное согласование протокола реального пилота.
