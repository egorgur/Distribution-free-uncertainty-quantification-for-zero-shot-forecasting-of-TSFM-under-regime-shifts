## 2. Технические наблюдения (проверено по коду/кешу 2026-11-18)

### 2.1. Multi-Context на synth_v1 почти бесплатен

- Окна идут с шагом 8 по d, поэтому окно t−16 того же ряда уже есть в кеше **для всех четырёх L**. Его первые 16 шагов — честный hindcast каждой длины: контекст кончается в t−16, скрытые 16 точек в него не входят. Так уже сделан S2.
- У Bolt прогноз H16 = префикс H64 (разница 0) — hindcast берётся из H64. У Chronos-2 H16 считался отдельным вызовом — брать его, не префикс H64.
- **Ограничение:** для d = −128 и −120 окна d−16 в сетке нет (сетка начинается с d = −128, t = 520; для d = −128 ещё и t−16 = 504 < 511, L512 невозможен) → эти окна выпадают из общей выборки hindcast-методов. Общая выборка всех методов — одинаковая (предложение: d ≥ −112).
- Hindcast длиной 8 тоже доступен (окно t−8). Длина 16 в инструкции — пример.
- Итог: пилот Multi-Context на Bolt seed 0/1 и Chronos-2 seed 0 **не требует нового инференса**; на Chronos-2 seed 1 проверить, что посчитаны оба горизонта у всех четырёх длин.

### 2.2. Regime-Aligned и компонентная адаптация требуют новых прогнозов

На окно: кандидаты Level, Level+Scale, Trend (Original и Short — из кеша) × 2 вызова (hindcast на t−16 по статистикам префикса + итоговый на t) = 6 новых прогнозов. 32 980 окон × 6 ≈ 200 тыс. прогнозов ≈ 35 мин Bolt на CPU ноутбука (10 мс) или ~15 мин на втором компьютере. Сетка частичной коррекции α ∈ {0.25, 0.5, 0.75} × 3 выравнивания × 2 вызова — ещё ≈ 600 тыс. (~1.7 ч). Chronos-2 — на GPU, по два горизонта. Новые прогнозы — **в отдельный кеш**, исходный не трогать.

### 2.3. Онлайн-калибровка упирается в короткий прогрев

- Источники прогнозов на synth_v1 — раз в 8 точек, а до смены всего ~128 точек истории с допустимым L512 (первое окно d = −128). Полная H64-ошибка созревает через 64 точки → **до смены почти нет созревших H64-остатков**; калибратор стартует практически в момент смены.
- Варианты (решить до расчёта): (а) пошаговые остатки шага h, созревшие к t (h = 1…8 доступны быстро); (б) тёплый старт калибратора по рядам контроля none — это перенос с других рядов, описывать отдельно; (в) новая синтетика с длинным префиксом до смены и плотными началами прогнозов (шаг 1–4). **Рекомендация:** (в) как основной стенд направления 4 (одновременно даёт новые подтверждающие данные), (а) — разведка на synth_v1.

### 2.4. Прочее

- cascade.npz хранит только скалярные метрики обрезок; для WIS по новой нормировке хватает CRPS/coverage/width, для смешивания/калибровки обрезки нужны квантили (≈ 83 тыс. прогнозов на seed у Bolt, ~4 мин).
- Trend Alignment: оценка наклона на коротком недавнем участке смещена сезонностью (периоды 12/24/48 при участке 64). Нужен заранее заданный устойчивый к сезонности оценщик (например, наклон по целым периодам или Theil–Sen после сезонной разности) — согласовать, не подбирать по результату.
- Масштабы рядов до 1e±2 → все статистики выравнивания и сравнения в единицах std/MAD контекста (подводный камень `CLAUDE.md` разд. 9).
- Залипание (freeze) даёт MAD = 0 на участке → защита малого MAD обязательна, правило — до расчёта.

## 4. Подробный план по шагам

### P0. Общая основа оценки (до любого расчёта v3)

**Согласовать с пользователем (мои предложения по умолчанию):**

1. **Выборки.** Разведка — synth_v1 seed 0 (оценка) + seed 1 (настройка порогов/весов, как в v2). Подтверждение — новые seeds (2, 3) того же генератора или synth_v2 из 2.3, выделенные **до** настройки и не открываемые до фиксации методов.
2. **Основная конфигурация пилота:** Chronos-Bolt-small, H = 64, полный контекст L512; H16 и Chronos-2 — вторично.
3. **Общая выборка окон:** d ≥ −112 (есть hindcast для всех L), одинаковые исключения для всех методов.
4. **Нормировка:** общий знаменатель для всех методов — устойчивый эталон **Full L512** того же ряда из протокола v1 (а не эталон каждого метода), чтобы метод не «выигрывал» ухудшением своего знаменателя. Основная точечная метрика — rel MAE = MAE_метода / эталон_Full; парное сравнение — log(MAE_метода / MAE_Full) на том же окне.
5. **Transition Gain (TG):** TG₆₄ = 1 − exp(среднее по рядам log(MAE_метода/MAE_Full)) по окнам 0 ≤ d < 64; TG₁₂₈ — по 0 ≤ d < 128 (вложены, не независимы). Агрегация по ряду, затем по рядам; бутстреп по рядам.
6. **Stable Harm (SH):** то же отношение на рядах none (основное) и на d < −64 (дополнительное); SH = exp(среднее log) − 1. Допуск вреда (например ≤ 1%) — решение пользователя.
7. **Вероятностные метрики:** WIS по 9 квантилям (= квантильная аппроксимация CRPS через quantile loss, `src/metrics.py`), нормированный тем же знаменателем; покрытие и ширина 80%.
8. **d* методов:** функция `recovery_v1` без изменений; порог — по контролю **базового Full L512** (одна шкала), с чувствительностью к порогу по контролю самого метода.
9. **Стоимость:** число вызовов модели на окно, время на свободной машине, отдельно hindcast/детекторы/преобразования.
10. **Критерий успеха H7/H8 (предложение):** TG₆₄ > 0 с 95% бутстреп-интервалом выше 0 на всех сменах (основное, Bolt H64, seed 0) **и** SH не хуже допуска; разбивки по типам — описательные. Пересмотр на подтверждающих данных — повторение знака.

**Реализация:** `src/adaptation/evaluate.py` — общий слой: сбор метрик окна для любого набора квантилей, TG/SH/WIS, d* по общему порогу, бутстреп по рядам (переиспользовать `src/evaluation.py`, `src/metrics.py`). Тесты на синтетических массивах: TG = 0 для метода-копии, SH на none, знаменатель общий.

**Выход:** строки в `docs/decisions.md`, `docs/protocol_v3_multicontext.md` (по образцу `protocol_h1_h3.md`).

### P1. Пилот Multi-Context (H7)

**Кандидаты:** прогнозы L ∈ {64, 128, 256, 512} из кеша.

**Согласовать (предложения):**
- Оценка надёжности длины L в момент t — hindcast-ошибка h_L = MAE медианы окна t−16 по длине L на x[t−15…t], в единицах масштаба контекста. Альтернативные признаки из инструкции (ширина интервала, согласованность с другими длинами) — как отдельные варианты правила, заданные заранее, не перебор после результатов.
- **Жёсткий выбор:** L* = argmin h_L; при равенстве (|Δ| < 1e-6 std) — более длинный контекст; при NaN — L512 (fallback).
- **Мягкое смешивание:** w_L ∝ exp(−h_L / T) (softmax); температура T — подбирается только на seed 1 из заранее заданной сетки, либо фиксирована как медиана h на контроле. Простой контроль — равные веса.
- **Объект смешивания:** основной — **смесь распределений** (квантили смеси находятся численно: CDF каждого кандидата строится кусочно-линейной интерполяцией 9 квантилей с хвостами, затем решается Σ w_L F_L(y) = q). Дополнительный — среднее одноимённых квантилей (Винсентизация), называть так и не путать со смесью.
- Сглаживание весов во времени — нет в первом пилоте (окна идут с шагом 8; сглаживание — отдельная абляция).

**Сравнения (как в инструкции):** Full L512; Short L64 и L128; Oracle Trim и Detected Trim (из cascade.npz); жёсткий выбор; смешивание (+ равные веса). Метрики — по P0; разбивка по типам/силам/d; контроль none и drift/anomaly отдельно.

**Реализация:**
- `src/adaptation/multicontext.py`: `hindcast_errors(...)`, `select_length(...)`, `mix_weights(...)`, `mixture_quantiles(...)`, `vincent_quantiles(...)`.
- `scripts/adapt_multicontext.py`: читает кеш, без инференса; → `results/adapt_multicontext_v1/<модель>/` (таблицы, веса/выбор по окнам, конфиг, версии, `summary.md`).
- Тесты: причинность (hindcast не видит x[t+1…], окно t−16 кончается в t−16), квантили смеси монотонны, смесь одинаковых распределений = исходное, веса суммируются в 1, fallback.
- Сверка: Full и фиксированные L совпадают с этапом 3/протоколом v1 по MAE на общих окнах.

**Выход:** `docs/results/adapt_multicontext.md`, строка в разд. 8 `CLAUDE.md`, `docs/progress.md`.

### P2. Regime-Aligned Context (H8)

**Согласовать (предложения):**
- Разбиение old/recent: **основное — фиксированный недавний участок W = 64 точек** (без детектора, тип и τ не используются); вариант — граница по τ′ детектора этапа B (если τ′ не найдена — Original).
- Level: x_old − med_old + med_recent. Level+Scale: med_recent + (MAD_recent/MAD_old)(x_old − med_old); коэффициент ограничить [1/10, 10]; при MAD < 1e-3·std контекста — откат на Level. Trend: наклон Theil–Sen по сезонно-устойчивой схеме на old и recent, старый тренд удаляется, недавний добавляется с непрерывностью на стыке.
- Выбор кандидата (Original, Short L64/L128 — уточнить, Level, Level+Scale, Trend) по hindcast 16 точек: все статистики — по префиксу до t−16; после выбора вариант перестраивается по всей истории до t.
- Частичная коррекция: α ∈ {0, 0.25, 0.5, 0.75, 1} — сначала как абляция с фиксированным α (отчёт по всем), затем правило выбора α по тому же hindcast. α по будущему не выбирать.
- Дополнительно (если время): смесь выровненных вариантов весами из P1.

**Реализация:**
- `src/adaptation/alignment.py`: чистые функции преобразования (numpy, без модели), с защитами.
- `scripts/cache_aligned.py`: строит контексты, прогнозирует батчами, пишет в `results/cache/synth_v1[_seed1]/<модель>/aligned_v1/` (+ мета, хеш конфига, сверки: Original через тот же путь = кеш L512; одиночный = батч).
- `scripts/adapt_aligned.py` → `results/adapt_aligned_v1/`.
- Тесты: Level переносит 10, 11, 9 → 20, 21, 19 (пример инструкции); Level+Scale даёт med/MAD recent; Trend сохраняет остатки; α = 0 → исходный контекст; причинность (изменение x после t−16 не меняет hindcast-контекст).

**Анализ:** H8 = выбранный/фиксированный Aligned против Short и Oracle/Detected Trim (удаление истории), а также против Full. Ошибки выбора: доля окон, где hindcast выбрал не лучший на будущем кандидат (оптимизм выбора). Вред на none.

### P3. Regime-Component Adaptation (H9)

**Согласовать (предложения):**
- Статистики old vs recent (тот же W = 64): Level — |Δmedian|/MAD_old; Scale — |log(MAD_recent/MAD_old)| (+IQR); Trend — |b_recent − b_old| в единицах MAD; Frequency/Seasonality — сдвиг главного пика периодограммы / ACF на лагах периода.
- Пороги — по рядам **none seed 1**: квантиль 95% каждой статистики (≈ 5% ложных тревог на компоненту), как пороги d* в протоколе v1. Ни одна выше порога → **No Adaptation**. Несколько выше → наибольшее нормированное превышение (правило фиксируется заранее). AR не сводится к компонентам: ожидаемо No Adaptation или Short; отчёт отдельно.
- Реакции: Level → Level, Scale → Level+Scale, Trend → Trend, Freq/Season → Short L64 (или смешивание P1 с усилением короткого) — выбрать один основной до расчёта.
- **Oracle Component:** истинный тип → та же реакция с тем же разбиением W = 64 (τ не сообщается); соответствие типов: mean/sensor_bias→Level, variance→Scale, trend→Trend, seasonality/frequency→Freq, ar→No Adaptation (решить), none→No Adaptation.
- **Detected Component** — то же, тип по правилу выше.

**Реализация:** `src/adaptation/components.py` (статистики, правило); прогнозы берутся из кеша P2 (Short — из основного кеша), нового инференса почти нет. `scripts/adapt_components.py` → `results/adapt_components_v1/`.

**Анализ:** матрица ошибок детектора компонент по типам (и по d); Oracle − Detected = цена распознавания; сравнение с единой стратегией (Aligned без компонент, Multi-Context, Full, Short, Oracle Trim); Stable Harm на none.

### P4. Adaptive Uncertainty (вопрос направления 4, онлайн-калибровка)

Явно помечать во всех текстах: **внешняя целевая онлайн-калибровка, веса TSFM заморожены.** Без формальных гарантий.

**Сначала инфраструктура причинности:** `src/adaptation/online.py` — поток прогнозов ряда (начало u, шаг h, квантили), очередь созревания: остаток (u, h) доступен с момента u + h; калибратор в момент t видит только созревшие. Тесты: ни один остаток не используется раньше u + h; полная H-ошибка — только с u + H.

**Варианты (по порядку):**
1. Ширина: множитель интервала вокруг медианы, обновление по частоте недавних промахов (ACI-подобно: θ ← θ + γ(промах − 0.2)), медиана не меняется.
2. Центр: b_t = медиана созревших остатков y − ŷ (окно памяти), сдвиг интервала; отдельно — сдвиг выдаваемой медианы (тогда меняется и MAE, отчитывать отдельно).
3. Центр + ширина.
4. Последовательная конформная поправка: score = выход за интервал (max(q0.1 − y, y − q0.9, 0)) в единицах масштаба; поправка — эмпирический квантиль созревших score за окно памяти; прогрев и fallback = исходный интервал.
5. Несколько масштабов памяти (короткое/среднее/длинное) с весами по недавнему качеству (например, по quantile loss), идея как в P1.

**Стенд:** см. 2.3 — решить: (а) пошаговые остатки на synth_v1 (разведка) и/или (в) synth_v2 с длинным префиксом и плотными началами. Для (в) нужен новый конфиг и кеш (оценить объём до запуска).

**Метрики:** покрытие глобально / до смены / 0–64 / 0–128 / после восстановления; ширина; WIS; Recovery of Calibration (определить: первое d, после которого скользящее покрытие в допуске от 0.8 держится заданную длительность — по аналогии с d*); Stable Harm на none (ширина и WIS).

**Скрипт:** `scripts/adapt_uncertainty.py` → `results/adapt_uncertainty_v1/`.
