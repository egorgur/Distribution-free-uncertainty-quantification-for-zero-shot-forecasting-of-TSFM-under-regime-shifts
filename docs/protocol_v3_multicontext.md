# Протокол пилота Multi-Context (H7), версия 1

Дата: 2026-11-18. **Зафиксировано до расчёта.** Основа — решения пользователя от 2026-11-18 в `docs/decisions.md` (принятые рекомендации раздела 6 `docs/implementation_roadmap.md` и детали, принятые ответом «Согласен»). Формулы предложены ассистентом; в инструкции заданы только названия метрик. Прежний протокол H1/H3 v1 (`docs/protocol_h1_h3.md`) не меняется, из него берутся эталон и процедура d*.

**Статус выводов:** synth_v1 seed 0/1 уже изучены в v2, поэтому все выводы этого пилота — **разведочные**, не независимое подтверждение H7.

## 1. Данные и конфигурации

- Кеш: `results/cache/synth_v1` (seed 0, отчёт) и `results/cache/synth_v1_seed1` (seed 1, настройка). Нового инференса нет.
- Основная конфигурация: Chronos-Bolt-small, H = 64. Дополнительно, с той же процедурой и отдельной настройкой на seed 1: Bolt H = 16, Chronos-2 H = 64 и H = 16.
- Кандидаты: квантильные прогнозы одной модели из момента t по контекстам L ∈ {64, 128, 256, 512} (варианты кеша L64…L512), 9 квантилей 0.1…0.9.

## 2. Выборка окон

- Окна с pos ≥ −112 (у none — по pos), как на этапах 4 и 6: для pos = −128 и −120 нет окна t−16.
- Из оценки исключаются окна с MAE Full = 0 или без конечного эталона Full (одинаково для всех методов); их число записывается.
- Основная группа критерия — все change (7 типов × 3 силы, 210 рядов). drift и anomaly — описательно, отдельно.

## 3. Признаки надёжности длины в момент t

s(t) — наивный масштаб контекста L512 в момент t (средняя |Δx|, как у S2).

- **Hindcast (основной):** h_L(t) = mean_{j=0..15} |x[t−15+j] − med_L(t−16)[j]| / s(t), где med_L(t−16) — медиана прогноза окна pos−16 того же ряда по длине L. У Bolt — первые 16 шагов H64 (совпадает с H16), у Chronos-2 — отдельный кеш H16. Скрытые 16 точек не входят в контекст окна t−16.
- **Ширина (доп. а):** w_L(t) = mean_h (q0.9 − q0.1)_L(t) / s(t) по прогнозу на оцениваемый H.
- **Согласованность (доп. б):** c_L(t) = среднее по L′ ≠ L, 9 квантилям и шагам горизонта |q_k,L(t) − q_k,L′(t)| / s(t).

Если s(t) = 0 или не конечен (залипание), признак не определён → окно получает Full L512; число таких окон записывается.

## 4. Методы

| Код | Метод | Прогнозов модели на окно в онлайн-работе |
| --- | --- | --- |
| full | Full L512 | 1 |
| L64, L128 | фиксированный короткий контекст (L256 — описательно) | 1 |
| oracle_trim | обрезка по истинной τ: П4 из `cascade.npz` (change/drift при 31 ≤ d < 511, иначе Full) | 1 |
| det_trim | обрезка по найденной τ′: П2 этапа 6 (уровень модели этапа B, порог FAR 5% по seed 1; иначе Full) | 1 + детектор |
| rag | reset-and-grow П3 — дополнительно | 1 + детектор |
| sel_X | жёсткий выбор: argmin признака X; при разнице < 1e-6 — более длинный L | hindcast: 4 (+4 прогноза из t−16, которые в онлайн-работе уже сделаны); ширина/согласованность: 4 |
| mix_X | смесь распределений с весами w_L ∝ exp(−X_L / T) | то же |
| vin_X | среднее одноимённых квантилей с теми же по форме весами (своя T) | то же |
| mix_eq, vin_eq | равные веса 1/4 (контроль) | 4 |

X ∈ {hind (основной), width, cons}. Основные методы H7 — **sel_hind** и **mix_hind**.

Метрики обрезок берутся из `cascade.npz` (квантилей там нет), поэтому обрезки участвуют только в точечных/интервальных метриках MAE, WIS, покрытие, ширина; для Chronos-2 — из его `cascade.npz`.

### 4.1. Температура

T = c · m, где m — медиана признака X по всем четырём длинам и окнам оценки рядов none seed 1 (своя для модели/H/признака), c ∈ {0.25, 0.5, 1, 2, 4}. c выбирается на seed 1 по минимуму средней по рядам (всем 340 рядам, контроль включён) средней по окнам оценки величины log(MAE метода / MAE Full); при равенстве — бо́льшее c. Отдельно для mix и vin. На seed 0 c не меняется.

### 4.2. Смесь распределений

1. Квантили каждого кандидата упорядочиваются по возрастанию (перестановка). Нарушения порядка в кеше есть только в окнах anomaly-freeze и не превышают 4% ширины 0.1–0.9 (проверено до расчёта на Bolt seed 0); число затронутых окон записывается. Отдельные кандидаты, Full и среднее квантилей используют квантили кеша без изменения.
2. CDF кандидата — кусочно-линейная через точки (q_k, τ_k), τ = 0.1…0.9, с хвостами: q(0) = q0.1 − (q0.2 − q0.1), q(1) = q0.9 + (q0.9 − q0.8) (наклон соседнего отрезка). Совпадающие квантили — скачок CDF (точечная масса).
3. CDF смеси G(y) = Σ w_L F_L(y); квантиль уровня τ — inf{y : G(y) ≥ τ}, вычисляется точно по кусочно-линейной форме G. Медиана смеси — её квантиль 0.5.

## 5. Показатели

Обозначения: r = MAE метода / MAE Full на том же окне; ref — эталон Full L512 того же ряда/модели/H по `add_ratios` протокола v1 (медиана устойчивого старого/нового режима, смесь при смене в горизонте), посчитанный по полной сетке до фильтрации.

- **Относительная MAE:** MAE метода / ref (общий знаменатель всех методов); сводно — геометрическое среднее по окнам зоны, затем по рядам.
- **Transition Gain:** TG₆₄ = 1 − exp(mean_рядов mean_окон log r) по change-окнам 0 ≤ d < 64; TG₁₂₈ — по 0 ≤ d < 128.
- **Stable Harm:** SH = exp(mean_рядов mean_окон log r) − 1 по всем окнам оценки рядов none (основное); дополнительно по change-окнам d < −64.
- **WIS** (квантильная аппроксимация CRPS: 2 · средняя pinball-потеря по 9 уровням, как `crps` в `src/cascade.py`) / ref WIS Full; те же TG/SH-сводки по WIS — описательно.
- **Покрытие и ширина** 80%-интервала по зонам: d < −64, −64 ≤ d < 0, 0–64, 64–128, 128–512, ≥ 512, none. Ширина — / ref ширины Full.
- **d*:** для каждой ячейки change/drift кривая log(MAE метода / ref) по d, `bootstrap_recovery` протокола v1 без изменений; основной порог — Q95 Full L512 этого model/H из `results/protocol_h1_h3_v1/stage3/<модель>/thresholds.csv`; чувствительность — Q90 Full и Q95 по контролю самого метода на seed 1 (`control_thresholds`). Для обрезок d* не считается, если нет полной кривой метрик.
- **Стоимость:** прогнозов модели на окно (таблица выше) и время расчёта метода по кешу (без инференса).
- Отношения логарифмируются с floor 1e-6, как в v1.

## 6. Неопределённость и критерий

- Бутстреп: 1000 выборок рядов с возвращением внутри оцениваемой группы, seed 0, одни и те же выборки для всех методов (парные сравнения); 95% процентильный интервал.
- **Критерий H7 (основной, Bolt H64, seed 0), отдельно для sel_hind и mix_hind:** нижняя граница 95% интервала TG₆₄ > 0 по всем change **и** верхняя граница 95% интервала SH на none ≤ 0.01. H7 считается поддержанной на synth_v1 (разведочно), если критерий выполнен хотя бы для одного из двух основных методов; в отчёте указывается, для какого, и что проверялись два метода.
- Сравнение с обрезками (часть формулировки H7 «и жёсткой обрезкой»): парное mean log(MAE метода / MAE обрезки) по change-окнам 0 ≤ d < 64 и по всем окнам оценки, против det_trim и oracle_trim, с интервалом — **описательно**, не часть критерия.
- Всё остальное (доп. признаки, vin, равные веса, H16, Chronos-2, разбивки по типам/силам/d, drift, anomaly, WIS, покрытие, d*) — описательно.
