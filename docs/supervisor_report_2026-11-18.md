# Отчёт о ходе работы — 18 ноября 2026

**Рабочая тема (план v3):** «Адаптация замороженных Time-Series Foundation Models к смене режима без дообучения самой модели». Окончательное название не согласовано.

**Состояние.** По «Инструкции по дальнейшей работе» составлен план четырёх направлений. Проверены первые три: адаптивный выбор/смешивание длин контекста (H7), согласование старой истории с новым режимом (H8) и реакция на изменившуюся компоненту (H9). **H7 и H8 отрицательные**, у H9 **основной критерий не выполнен**, подтверждение лишь частичное (раздел 4.4) — по критериям, записанным до расчёта. Все расчёты — на прежней синтетике synth_v1 (seed 0/1 уже изучены в v2), поэтому выводы разведочные. Модели — Chronos-Bolt-small (основная) и Chronos-2; веса не меняются.

Главный вывод двух пилотов: **не работает правило выбора, а не сами варианты.** Ошибка прогноза «назад» на 16 последних точках выбирает лучший вариант на уровне случайного (≈ 30% из 4 длин, ≈ 20% из 5 преобразований). Если бы выбирался действительно лучший вариант, ошибка в переходе снизилась бы на ≈ 6% (H7) и ≈ 9% (H8).

## 2. Что требовалось по инструкции

1. **Multi-Context** — использовать прогнозы по L = 64, 128, 256, 512 не только как сигнал (S4), но и для адаптации: жёсткий выбор длины или мягкое смешивание; сравнить с полным контекстом, коротким, обрезкой по истинной и найденной точке.
2. **Regime-Aligned Context** — не удалять старую историю, а сдвигать её уровень, масштаб или тренд к недавнему режиму; выбирать вариант прогнозом «назад»; проверить частичную коррекцию α = 0.25…1.
3. **Regime-Component** — определить изменившуюся компоненту и применить подходящую реакцию; Oracle против Detected; обязательно No Adaptation.
4. **Adaptive Uncertainty** — расширение/сдвиг интервала, последовательная conformal-коррекция, несколько масштабов памяти.

Метрики инструкции: относительная MAE, d*, покрытие, CRPS/WIS, стоимость, **Transition Gain** (выигрыш в первые 64/128 точек после смены) и **Stable Harm** (вред без смены).

## 3. Как оценивали (решения, принятые до расчёта)

- Ошибка — MAE метода к устойчивому эталону **полного контекста L512** того же ряда (общий знаменатель для всех методов, по протоколу v1 от 12 ноября).
- **Transition Gain** = 1 − геом. среднее MAE(метод)/MAE(L512) в окнах 0 ≤ d < 64 (сначала по окнам ряда, затем по рядам); **Stable Harm** = геом. среднее того же отношения на рядах без смены − 1.
- **Критерий H7:** нижняя граница 95% интервала Transition Gain > 0 **и** верхняя граница Stable Harm ≤ 1%. **H8** — то же плюс: лучше короткого контекста и обрезки по найденной точке в 0 ≤ d < 64.
- Бутстреп по рядам (1000 выборок), основная конфигурация — Bolt, H = 64; Bolt H16 и Chronos-2 — описательно.
- Прогноз «назад» берётся из окна на 16 точек раньше: скрытые точки не попадают ни в контекст, ни в статистики преобразований.
- Смешивание — **смесь распределений** (квантили смеси вычисляются точно по кусочно-линейным CDF), среднее квантилей — отдельный вариант.

Протоколы: `docs/protocol_v3_multicontext.md`, `docs/protocol_v3_aligned.md`.

## 4. Результаты

### 4.1 H7: выбор и смешивание длин

| Bolt H64 | Transition Gain [95%] | Stable Harm [95%] |
| --- | --- | --- |
| Выбор длины по ошибке «назад» | −0.031 [−0.042; −0.020] | +0.090 [+0.069; +0.112] |
| Смесь по ошибке «назад» | −0.009 [−0.018; 0.000] | +0.058 [+0.048; +0.069] |
| Обрезка по истинной точке (ориентир) | −0.060 | 0 |

- Критерий не выполнен ни в одной из 4 конфигураций и ни у одного варианта (ошибка «назад», ширина, согласованность длин; выбор, смесь, среднее квантилей, равные веса).
- Смешивание повышает покрытие 80%-интервала, но **везде**: в переходе 0.72 → 0.79, без смены 0.85 → 0.87. Это общее расширение, а не адаптация неопределённости.
- Распределение выбранных длин одинаково в переходе и в стабильном режиме — признак по 16 точкам не различает эти ситуации.

### 4.2 H8: согласование истории

Недавние 64 точки не меняются, старые 448 сдвигаются/масштабируются/получают новый тренд.

| Bolt H64 | Transition Gain | Stable Harm | / L64 | / обрезка по найденной точке |
| --- | --- | --- | --- | --- |
| Выбор из 5 вариантов | −0.058 | +0.120 | 0.927 | 1.057 |
| Всегда сдвиг уровня | 0.000 | +0.043 | | |
| Всегда сдвиг уровня, α = 0.25 | +0.002 | +0.005 | | |
| Всегда коррекция тренда | −0.107 | +0.211 | | |

- Частичная коррекция снижает вред почти пропорционально силе, но так же исчезает и выигрыш.
- По типам смены (без выбора): сдвиг уровня полезен при смене среднего и смещении датчика, коррекция тренда с α = 0.5 — при смене тренда; при AR, сезонности и дисперсии все преобразования вредят. Полная коррекция тренда вредна почти везде — вероятно, наклон по 64 точкам искажается сезонностью (это ограничение записано заранее).

### 4.3 Стоимость

H7 — без новых прогнозов (по кешу), ≈ 11 мин на конфигурацию на CPU. H8 — 12 новых прогнозов на окно: Bolt 27 мин CPU, Chronos-2 39 мин GPU (GTX 1070).

### 4.4 H9: реакция на изменившуюся компоненту

Протокол — `docs/protocol_v3_component.md`, выводы — `docs/results/adapt_components.md`. Новых прогнозов не потребовалось.

| Bolt H64, 0 ≤ d < 64 | Значение |
| --- | --- |
| MAE(специализация при известном типе) / MAE(всегда сдвиг уровня) | 1.018 [1.000; 1.038] — критерий не выполнен |
| Специализация, тип определяется по данным: Transition Gain / Stable Harm | −0.037 / +0.053 |
| Цена ошибок распознавания типа (при том же моменте вмешательства) | ≈ 3.4% ошибки (Chronos-2: 5.1%) |

Правильные пары «тип → реакция» есть, но реакции инструкции для сезонности и дисперсии неудачны, и это съедает выигрыш. Исправлять отображение по этим же данным нельзя — только новым протоколом на новых данных.
